# 🍍 凤梨数据库 FongleeDB

## 💡 项目简介

**FongleeDB** 是一个从零开始构建的 **完整关系型数据库管理系统（DBMS）**。与传统数据库系统不同，FongleeDB 的 **SQL 解析器、执行引擎、存储引擎、磁盘管理、网络通信等核心模块** 均由作者自主实现，未依赖任何第三方数据库组件或黑盒模块。

在许多主流数据库系统中，SQL 解析与执行通常由一个模块处理，而存储、索引、事务等功能则交由独立的存储引擎（如 InnoDB）负责。这种模块化设计虽然提高了灵活性，但也增加了系统的复杂性和黑盒程度。相比之下，FongleeDB 提供了一个 **从 SQL 到磁盘的全链路、自洽的数据库系统**，所有内部行为均为透明可控，适合深入理解数据库内部机制的开发者和研究人员。

---

## ✨ 核心特性

* **完整自研架构**：涵盖 SQL 解析器、执行计划生成器、存储引擎、磁盘管理、网络通信等核心模块，全部由作者自主实现。
* **模块高度透明**：无任何黑盒模块，所有内部行为均可追踪和修改，适合深入学习和研究数据库内部机制。
* **高性能表现**：在非事务模式下，`INSERT` 操作的性能表现优于 MySQL，具体测试结果详见下文。
* **灵活的扩展性**：支持自定义存储策略、网络通信协议等，便于根据实际需求进行扩展和优化。
* **适合实验与研究**：为数据库相关的实验、教学和研究提供了理想的平台。

## 🛠 当前支持的 SQL 功能

已支持的基本 SQL 指令包括：

```sql
SHOW TABLES;
CREATE TABLE users (id INT32 INDEX, name STRING(16) NOT NULL, password STRING(20));
SHOW COLUMNS FROM users;
INSERT INTO users (id, name, password) VALUES (143589, 'x0x0x8x', '5220015');
SELECT * FROM users WHERE id = 500000;
DELETE FROM users WHERE name = 'x0x0x8x';
DROP TABLE users;
```

说明：

* 表结构定义支持类型约束、索引、长度限制等语义。
* `SELECT` 语句支持基本的 `WHERE` 条件。
* `INSERT` 操作在非事务模式下性能表现优异，初步测试显示在某些场景下性能可达 MySQL 的 20\~30 倍。通过 `SHOW PROFILE` 检查，MySQL 的时间主要耗费在 `COMMIT` 阶段，推测与其默认的事务处理策略有关。FongleeDB 当前未实现事务机制，因此避免了相关的磁盘 IO 开销。

## 🔧 使用说明

1. 修改 `initStorageEngine` 函数参数为希望存储数据的目录（目录必须已存在）。
2. 编译并运行所有源代码（推荐使用 Visual Studio）。
3. 默认运行方式为交互模式，可在 `TableHandleTestTask.c` 文件中切换为自动测试模式。
4. 多种参数配置分散在若干 `.h` 文件中，建议自行探索。
5. 当前仅支持 Windows 系统，Linux 支持计划中。

## 📊 与其他数据库系统的对比

| 特性      | FongleeDB        | 其他主流数据库系统（如 MySQL、PostgreSQL、Oracle） |
| ------- | ---------------- | ------------------------------------ |
| 架构设计    | 完整自研，模块高度集成      | 模块化设计，部分功能依赖第三方组件或插件                 |
| 存储引擎    | 自主实现，支持自定义存储策略   | 通常使用内置或第三方存储引擎（如 InnoDB）             |
| 网络通信    | 自主实现 Socket 通信协议 | 使用标准协议，部分细节不可控                       |
| 模块透明度   | 高，所有模块均可追踪和修改    | 部分模块为黑盒，难以深入研究                       |
| 扩展性     | 高，可根据需求自定义和扩展    | 受限于现有架构和插件机制                         |
| 适合的用户群体 | 开发者、研究人员、数据库爱好者  | 企业用户、普通开发者                           |

说明：

* Oracle 数据库采用模块化设计，部分功能可能依赖第三方组件或插件，但其具体实现细节未完全公开，透明度相对较低。
* MySQL 和 PostgreSQL 等开源数据库系统虽然开放源代码，但其架构设计仍采用模块化方式，部分功能由独立的存储引擎或插件提供。
